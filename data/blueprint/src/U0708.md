| Term | Meaning |

### Cloud, fog and edge — models and terms
## 1. Cloud characteristics and service models
- 5 essential characteristics:
- On-demand self-service
- Ubiquitous network access
- Metered use
- Elasticity
- Resource pooling
| Service model | User gets | Example |
| IaaS | Servers, storage, network | Amazon EC2 [GK] |
| PaaS (Platform as a Service) | Platform to build/run apps | Google App Engine [GK] |
| SaaS | Ready software over the web; accessible on mobile; UI and fields customisable | Outlook, Gmail [GK] |
- ⚠ Trap: "Hardware as a Service" is not an independent layer; spectrum allocation is not a cloud service (PYQs)
## 2. Underlying technologies → meaning
| Term | Meaning |
| Virtualisation | One physical server runs many virtual machines, each with its own OS [GK] |
| Containers | Lightweight packages of an app with its dependencies that share the host OS kernel (e.g. Docker) [GK] |
| Serverless | Developer writes functions; the cloud provider runs and scales servers, billing per use (e.g. AWS Lambda) [GK] |
| Grid computing | Pools distributed resources for large simulations |
## 3. Edge vs fog vs cloud
| Model | Where processing happens | Use |
| Cloud | Distant centralised data centres | Heavy storage and analytics |
| Fog | Between the edge and the cloud, when edge devices lack power | Local aggregation |
| Edge | On or near the device | Lowest latency, real-time (e.g. a camera sends only suspicious clips) |
- Edge computing: Saves bandwidth; keeps sensitive data local
- ⚠ Edge = lowest latency; fog = in between; cloud = distant centres
