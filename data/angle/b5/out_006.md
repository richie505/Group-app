=== ROW 29 | Cyber security concerns - types of cyber crime, malware, ransomware, phishing, social engineering

## Security principles, cryptography terms and tools → function | from: S0, S1
# 1. Principles and cryptography terms
- **CIA triad:** cyber threats compromise **confidentiality, integrity or availability** of information
- **Cryptography:** encoding information so only authorised parties can read it (encryption = data readable only by authorised parties)

| **Term** | **Key point** |
|---|---|
| Encryption / decryption | Plaintext to ciphertext and back using a key [GK] |
| **Symmetric** | Same secret key for both (e.g., AES) - fast, key-sharing problem [GK] |
| **Asymmetric** | Public-private key pair (e.g., RSA) - basis of PKI [GK] |
| Digital signature | Signed with sender's private key, verified with public key; proves origin and integrity [GK] |
| Hashing | One-way, fixed-length digest (e.g., SHA-256); any change alters the hash [GK] |

- ⚠ **Symmetric** = one shared key (AES); **Asymmetric** = public-private pair (RSA)
- !! Not in your sources: cyber insurance cover for individuals (IRDAI-approved retail cyber policies) - add from a current source.
# 2. Security tools → function

| **Tool** | **Function** |
|---|---|
| **Firewall** | **Prevents illegal (unauthorised) network access** (APPSC-GS 2025 PYQ) |
| **Antivirus** | Prevents and heals infections |

| **Honeypot** | Decoy system that lures attackers to study them |

- **Cyber security scope:** firewalls, encryption, passwords
- ⚠ **Firewall** = blocks unauthorised access; **Antivirus** = prevents and heals infections

## Malware types → mechanism and example | from: S2
- **Malware:** software designed to disrupt, damage or gain unauthorised access to a computer system
  - APPSC 2024 key answer for this definition: **Virus** (PYQ)

| **Type** | **Spreads by / how it works** | **Example** |
|---|---|---|
| **Virus** | Attaches to files/programs; needs user to execute (user must run it); corrupts/deletes data | - |
| **Worm** | Self-replicates automatically across networks **without user interaction**; eats bandwidth; fastest spreading | WannaCry |
| **Trojan** | Disguised as legitimate software; **does not self-replicate**; opens backdoors | Zeus Trojan |
| **Ransomware** | Spreads via phishing, malicious downloads; **Encrypts** files/systems, demands ransom (often crypto) for key | AIIMS Delhi attack (2022) |
| **Spyware** | Spreads via bundled software, malicious links; secretly monitors user (secret surveillance), steals passwords/banking data | Pegasus |
| **Adware** | Unwanted ads; bundled with free/pirated software | Fireball |
| **Rootkit** | Deep admin-level access; **hides** other malware; hardest to detect | Stuxnet components |
| **Keylogger** | Hidden install; records every keystroke (passwords, PINs, OTPs, card numbers) | DarkHotel |
| **Botnet** | Network of infected "zombie" devices controlled remotely; used for DDoS (massive DDoS attacks), spam, crypto-mining | Mirai (hijacked IoT devices) |

- ⚠ **Virus** = user must run it; **Worm** = spreads without user interaction
- ⚠ **Rootkit** = hides other malware; **Keylogger** = records keystrokes
> Exam angle: "self-replicating without user action" = worm; "no self-replication, disguised" = trojan.

## Attack techniques → meaning | from: S4

| **Threat / technique** | **Description / meaning** |
|---|---|
| **Phishing** | Deceptive emails/messages that appear legitimate (posing as a legitimate source) to extract passwords or financial details |
| Vishing | Phishing by voice calls [GK] |
| **Zero-day exploit** | Exploits an unknown, unpatched flaw with no patch - developers have had "zero days" to fix it; e.g., Pegasus |

=== ROW 30 | Cyber security architecture - IT Act 2000 and amendments, CERT-In, NCIIPC, Cyber Swachhta Kendra, I4C

## IT Act, 2000 — purpose, concepts and framework | from: S0
# 1. Purpose and concepts
- **Purpose:** **IT Act, 2000** gives **legal recognition to transactions by electronic data interchange** and other electronic communication ("**electronic commerce**") (APPSC 2018 PYQ)
  - Also legal recognition of **electronic records and e-commerce** transactions + prevention of computer-based crimes
- **Concepts introduced:** **electronic record, digital signature, certifying authority** - "all of the above" (MPPSC 2021 PYQ)
- **Status:** primary law on cyber crime and e-commerce in India
- **Amended:** **2008**
# 2. Bodies and framework
- **Statutory bodies:** **Controller of Certifying Authorities** (statutory regulator of electronic signatures) + **CERT-In**
- **Framework:**
  - Defines cyber contraventions and crimes with an **adjudication framework**
  - Security of sensitive personal data
  - **due diligence by intermediaries**
  - A **special Act** that overrides IPC provisions where the crime is squarely covered

=== ROW 32 | Data protection and privacy - Puttaswamy judgment, Digital Personal Data Protection Act, data localisation

## Right to privacy — Puttaswamy and earlier cases | from: S0
# 1. Puttaswamy (2017)
- **K.S. Puttaswamy v. Union of India (2017)** (K.S. Puttaswamy v UoI): Declared **Right to Privacy a Fundamental Right** under **Art. 21** (**Article 21**) and Part III; also linked to Art. 19
  - Privacy intrinsic to life and liberty (PYQ 2022)
- **Bench:** **Nine-judge** bench (**9-judge bench, unanimous**); **24 August 2017**
- **Overruled:** **M.P. Sharma (1954)** and **Kharak Singh (1962)** to the extent they denied privacy
# 2. Cases → point

| **Case** | **Point** |
|---|---|
| Kharak Singh v State of UP (1962) | Early recognition of privacy concerns under Art. 21 (CDI) |
| Gobind v State of MP (1975) | Privacy recognised as part of personal liberty (CDI) |
| Puttaswamy (2017) | Privacy a fundamental right; informational privacy (CDI) |

# 3. Tests and follow-up
- **Tests for state intrusion/restriction:** **Legality** (a law), **legitimate aim / need**, **proportionality**
  - Later applied to Aadhaar (2018)
- **Follow-up:** Directed government to enact a data-protection law → **Digital Personal Data Protection Act 2023**, with a **Data Protection Board**
- ⚠ Puttaswamy = **9** judges, unanimous (2017); Aadhaar = 5 judges, 4:1 (2018)

## DPDP Act, 2023 — scope, terms → meaning, exemptions | from: S4
# 1. The Act
- **Passage:** **August 2023**; Presidential assent **11 August 2023**
- **Scope:**
  - Data processed digitally or collected digitally; excludes non-personal data
  - Covers entities in India + those offering goods/services to people in India from abroad
  - Gender-neutral wording
# 2. Terms → meaning

| **Term** | **Meaning** |
|---|---|
| **Data Principal** | Individual whose data is processed (gender-neutral term); parent/guardian for a child (under 18) |
| **Data Fiduciary** | Decides purpose and means of processing |
| **Significant Data Fiduciary** | Notified by Centre on volume/sensitivity/risk; extra duties: must appoint a DPO in India, independent auditor, impact assessment |
| **Consent Manager** | Registered entity through which a principal gives, manages and withdraws consent |

# 3. Exemptions and State processing
- **Exemptions (Sec. 17):** Centre can exempt state instrumentalities - notified State agencies (sovereignty, security, public order)
  - E.g., law enforcement exempt from consent during biometric surveillance
  - Research, archiving and statistics exempt
  - **Startups** can be exempted; journalism gets no exemption
  - Criticised as broad government exemptions
- **Section 7:** "Legitimate uses" lets the State process data without consent

## DPDP — rights, duties, Board and penalties | from: S5, S6
# 1. Data Principals' rights and duties
- **Rights:** Information/access, **correction, erasure**, grievance redress, **withdrawal of consent**, nomination
- **Duties:** No false information or impersonation; no frivolous complaints
# 2. Children's data
- **Consent:** **Verifiable parental consent** for under-18s
- **Bans:** **No tracking, behavioural monitoring or targeted ads** aimed at children
# 3. Data Protection Board of India
- **Nature:** Adjudicatory body set up by the Centre; HQ **New Delhi**; members appointed by the Central Government
- **Appeals:** Lie to **TDSAT**
- **Commencement:** Board provisions took effect **immediately** with the final Rules (Nov 2025)
  - Earlier (2026 notes): Board "prepared", awaiting commencement
- !! Not in your sources: Board's strength and first appointments.
# 4. Penalties

| **Breach** | **Maximum penalty** |
|---|---|
| Failure of reasonable security safeguards | **Rs 250 crore** |
| Obligations regarding **children's data** | **Rs 200 crore** |
| Additional duties/obligations of **SDFs** | **Rs 150 crore** (₹150 crore) |
| Residual breach | **Rs 50 crore** |
| Duties of Data Principals (false information) | **Rs 10,000** (up to ₹10,000) |

- ⚠ **250 – 200 – 150 – 50** crore = **security safeguards – children – SDFs – residual**

## Data localisation and cross-border transfers | from: S9
- **RBI (April 2018):** All payment-system data stored **only in India**

## Global frameworks — GDPR, Right to be Forgotten, DPDP vs GDPR | from: S10
# 1. GDPR
- **GDPR:** Adopted by the **European Union** in **April 2016**; implemented from **25 May 2018** (UPSC 2019 PYQ)
# 2. Right to be Forgotten (RTBF)
- **Meaning:** Removal, masking or de-indexing of outdated, irrelevant or harmful personal information
- **Origin:** EU case **Google Spain v. AEPD (2014)**; formalised as the **'Right to Erasure'** in GDPR (Art. 17)
- **In India:**
  - Part of privacy under **Art. 21** (Puttaswamy); not absolute
  - Does not erase judicial records; only limits name-based searches
  - DPDP Act gives a **Right to Erasure (Sec. 12)** (DPDP **Section 12**); no standalone law
  - **UoI** framework to de-index name searches of acquitted persons
- ⚠ Right to Erasure = GDPR **Art. 17**; DPDP **Sec. 12**
# 3. DPDP Act vs GDPR

| **Point** | **DPDP Act 2023 (India)** | **GDPR (EU)** |
|---|---|---|
| Scope | Only **digital** personal data | All personal data |
| Terms | **Data Principal / Data Fiduciary** | Data Subject / Data Controller |
| Regulator | **Data Protection Board of India** (adjudicatory) | Data Protection Authority in each member state (one DPA per member state) |
| Cross-border | **Blacklist** (allowed unless restricted) | Whitelist / adequacy |
| Penalties | Financial only, up to **Rs 250 crore** | Financial + criminal in some states |
| Portability | Not a statutory right | Explicit right |

- **Table source:** CDI Block15 (Part XI)
