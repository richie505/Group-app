## Industrial revolutions — stages, definitions and FIRSTs | from: S0, S3, S5
# 1. Stages 1.0 to 5.0
| **Stage** | **Defining technology** |
|---|---|
| Industry 1.0 | Mechanisation, **steam power**, weaving loom |
| Industry 2.0 | **Electricity**, mass production, assembly line |
| Industry 3.0 | **Automation, computers and electronics** |
| Industry 4.0 | **Cyber-physical systems**, IoT, networks, AI, big data |

- **Fourth Industrial Revolution:** Term coined by **Klaus Schwab**, founder of WEF, in **2016**
  - Digital + physical + biological technologies converging; **smart factories**
- **Industry 5.0:** Puts **human-machine collaboration** and people at the centre of industrial innovation
- ⚠ **3.0** = automation and computers; **4.0** = cyber-physical systems; **5.0** = human-machine collaboration

## IoT — layers, variants, IoT vs AI and RFID tags | from: S1, S2
# 1. Layers and variants
- **Three-layer model:**
  - **Perception:** sensors, RFID
  - **Network:** transmission
  - **Application:** smart services
- **Variants:** **IIoT** (industrial automation), **IoNT** (nano-devices), Internet of Mobile Things, mission-critical IoT (military)
# 2. IoT vs AI
| **IoT** | **AI** |
|---|---|
| Collects and exchanges data through sensors | Analyses data, recognises patterns, decides |
| Rule-based, limited learning | Machine and deep learning |
| Smart thermostat, fitness wearable | Chatbot, image recognition |

# 3. RFID tags - passive vs active
| **Tag** | **Power** | **How it responds** |
|---|---|---|
| Passive | **No internal battery**; powered by the reader's field [GK] | Reflects/backscatters the signal; cheap, short range [GK] |
| Semi-passive | Battery runs the chip only [GK] | Still uses the reader's field to reply [GK] |
| Active | Own battery **and** transmitter [GK] | Broadcasts itself; long range [GK] |

- ⚠ **Trap:** "passive tags are powered by an internal circuit" is **wrong** (APPSC-G1 2022 key: II and IV only)

## Ethical concerns, threats and challenges | from: S4, S5

- **Bias:** From non-representative training data

- **Explainability:** Deep models are "black boxes" → decisions hard to justify
# 2. Challenges for India
- **R&D spend:** India's GERD only **~0.64-0.7% of GDP**
- **Hardware:** GPU shortage + dependence on imported chips
- **Skills:** Shortage of frontier-AI skills (Jul 2026)

## Cloud, fog and edge — models and terms | from: S2, S3
# 1. Cloud characteristics and service models
- **5 essential characteristics:**
  - On-demand self-service
  - Ubiquitous network access
  - Metered use
  - Elasticity
  - Resource pooling

| **Service model** | **User gets** | **Example** |
|---|---|---|
| **IaaS** | Servers, storage, network | Amazon EC2 [GK] |
| **PaaS** (Platform as a Service) | Platform to build/run apps | Google App Engine [GK] |
| **SaaS** | Ready software over the web; accessible on mobile; UI and fields customisable | Outlook, Gmail [GK] |

- ⚠ **Trap:** "Hardware as a Service" is not an independent layer; spectrum allocation is not a cloud service (PYQs)
# 2. Underlying technologies → meaning
| **Term** | **Meaning** |
|---|---|
| Virtualisation | One physical server runs many virtual machines, each with its own OS [GK] |
| Containers | Lightweight packages of an app with its dependencies that share the host OS kernel (e.g. Docker) [GK] |
| Serverless | Developer writes functions; the cloud provider runs and scales servers, billing per use (e.g. AWS Lambda) [GK] |
| **Grid computing** | Pools distributed resources for large simulations |

# 3. Edge vs fog vs cloud
| **Model** | **Where processing happens** | **Use** |
|---|---|---|
| Cloud | Distant centralised data centres | Heavy storage and analytics |
| Fog | Between the edge and the cloud, when edge devices lack power | Local aggregation |
| Edge | On or near the device | **Lowest latency**, real-time (e.g. a camera sends only suspicious clips) |

- **Edge computing:** Saves bandwidth; keeps sensitive data local
- ⚠ **Edge** = lowest latency; **fog** = in between; **cloud** = distant centres

## Blockchain — definition and FIRSTs | from: S0, S2
- **Definition:** **Time-stamped series of immutable records** managed by a cluster of computers **not owned by any single entity** (APPSC 2018)
- **Visibility:** Records visible to relevant stakeholders **without risk of alteration**; database copies sit with participants (UPSC 2020, 2026)

| **FIRST** | **FACT** |
|---|---|
| **Bitcoin (2009)** | First cryptocurrency, created by pseudonymous **Satoshi Nakamoto** |

- **Bitcoin features:** Decentralised, peer-to-peer
  - **Public/private keys** and wallets
  - **Mining** validates transactions

## Terms → meaning (ledger, crypto, Web 3.0) | from: S0, S2, S3
| **Term** | **Meaning** |
|---|---|
| Distributed ledger | Shared ledger copied at many **nodes**; a "single source of truth" with no central validator |
| Block | Holds transaction details + **hash of the previous block** + **timestamp** |
| Hash | Cryptographic fingerprint; changing data changes the hash, so tampering shows |
| Node | A computer holding a copy of the ledger |
| Immutability | Once recorded, data is nearly impossible to alter without consensus |
| Consensus | Rule by which nodes agree on valid transactions |
| **Stablecoins** | Pegged to fiat, commodities or crypto |
| **NFTs** | Unique cryptographic tokens on a blockchain; can represent physical assets digitally |
| **Smart contracts** | Self-executing code on a blockchain → cut intermediaries, monitor supply chains |
| **Web 3.0** | Third-generation, decentralised web |
| **DeFi** | Lending and trading via smart contracts without banks |
| **Tokenisation** | Ownership rights in an asset → blockchain token (Jun 2026) |

- ⚠ NFTs: non-fungible → **not exchangeable at equivalency** (UPSC 2022 key: 1 and 2 only)

## Types — public vs private; PoW vs PoS | from: S0, S1
# 1. Public vs private
| **Public / permissionless** | **Private / permissioned** |
|---|---|
| Anyone can join, read and validate (Bitcoin) [GK] | Only authorised entities join and validate [GK] |
| Open ledger everyone can inspect, no single controller | Controlled by a consortium or organisation; e.g. **AP DigiVerify** |

# 2. Consensus mechanisms
| **Proof of Work (PoW)** | **Proof of Stake (PoS)** |
|---|---|
| Miners race to solve complex puzzles (Bitcoin) | Validators chosen by coins **staked**[GK] |
| **Very high energy use** | Far lower energy use [GK] |

- **The Merge:** Ethereum moved PoW → PoS in **Sep 2022**
- ⚠ Bitcoin = **public** + **PoW**; Ethereum = PoS since **Sep 2022**; **AP DigiVerify** = permissioned
